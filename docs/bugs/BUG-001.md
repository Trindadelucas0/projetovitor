# BUG-001 - Termos pedidos duas vezes (ALTA)

- **ID:** BUG-001
- **Data:** 2026-10-16
- **Perfil afetado:** aluno, personal (toda conta nova)

## Passos para reproduzir
1. Criar conta aceitando os termos.
2. Entrar no app.
3. O app pede os termos/privacidade de novo.

## Causa raiz
O cadastro (`auth.js`) e `POST /api/terms/accept` gravavam só `term_acceptances`; o gate (`termsStatus` → `legalStatus`) exige também `legal_acceptances` (termos_uso + privacidade). Resultado: `needs_terms` verdadeiro logo após aceitar.

## Correção (arquivos alterados)
- `app/api/legal.js`: nova `acceptBaseDocs(userId, req)`, que grava termos_uso + privacidade na versão vigente.
- `app/api/lgpd.js`: `acceptTerms` chama `acceptBaseDocs` antes de gravar `term_acceptances`.
- `app/frontend/src/App.jsx`: GuidedTabBar escondida enquanto houver `needs_terms`/`must_change_password`.

## Teste de regressão adicionado
`node --test test/qa-regressao.mjs` (API 8797, `DB_NAME=avagym_test`): "cadastro com aceite não pede os termos de novo" e "aceite pelo fluxo antigo também grava legal_acceptances". `e2e/qa-regressao.spec.js` (Playwright, front 4459 → API 8797): "aluno recém-cadastrado não vê os termos de novo".

## Lição / armadilha
Duas tabelas de aceite (legado e jurídico) precisam ser gravadas juntas. Todo gate novo exige revisar **todos** os caminhos que gravam o aceite.
