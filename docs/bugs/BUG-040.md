# BUG-040 - Remover cartão: payload sem id válido gerava 400 genérico

- **ID:** BUG-040
- **Data:** 2026-10-16
- **Severidade:** BAIXA
- **Perfil afetado:** aluno/profissional (#/assinatura, API de cartões)

## Passos para reproduzir
1. Cadastrar um cartão do simulador.
2. `POST /api/billing/cards/remove` com `{ "card_id": "<uuid>" }` (ou id inválido).
3. Resposta 400 com mensagem vaga; o cartão não era removido.

## Investigação (produção, 16/10/2026)
`request_audit` mostra 3 recusas (400) em 19:10:07, 19:10:09 e 19:10:11 BRT na conta teste.plano.gratis, num fluxo automatizado (adicionar cartão → assinar → remover em ~2 s, Chrome/130 Linux). A tela do app envia `{id}` e funciona; o cliente automatizado enviou o campo errado/ID não-UUID.

## Causa raiz
`app/api/billing/routes.js` só aceitava `id` e devolvia erro genérico para qualquer outro formato.

## Correção (arquivos alterados)
- `app/api/billing/routes.js`: aceita `id` ou `card_id`; id inválido → 400 "Informe o cartão a remover (id do cartão)." com `code: INVALID_INPUT`.
- Produção: os 3 cartões do simulador da teste.plano.gratis foram removidos pela própria rota (como o usuário).

## Teste de regressão adicionado
`app/api/test/v5-cartao-remover.mjs` (remoção por `id` e por `card_id`, cartões 4242 e 4000000000000002).

## Lição / armadilha
Mensagens de validação devem dizer qual campo falta.
