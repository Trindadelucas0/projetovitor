# BUG-033 - Logout não invalidava o avagym_token

- **ID:** BUG-033
- **Data:** 2026-10-16
- **Severidade:** ALTA
- **Perfil afetado:** todos (sessão)

## Passos para reproduzir
1. Fazer login e guardar o cookie avagym_token.
2. POST /api/auth/logout.
3. GET /api/auth/me com o token antigo: 200.

## Causa raiz
O logout só apagava o cookie no navegador; o JWT continuava válido até expirar (7 dias). Só o "sair de todos os aparelhos" e a troca de senha (token_version) invalidavam tokens.

## Correção (arquivos alterados)
- `app/api/auth.js`: todo token novo leva `jti`; `POST /api/auth/logout` grava o jti em `revoked_tokens` e `authUser` recusa token revogado (401). Token antigo sem jti: o logout sobe `token_version` (encerra as sessões antigas daquele usuário).
- `app/api/db/migrations/050_revoked_tokens.sql` (+ down). Linhas expiradas são limpas no próprio logout.

## Teste de regressão adicionado
`app/api/test/v5-logout.mjs` (cookie e Bearer dão 401 depois do logout; outra sessão continua 200).

## Lição / armadilha
Apagar o cookie não é logout em API stateless: o servidor precisa de revogação.
