# BUG-010 - Incidente PERSONAS_BASE/CASOS_DIR: testes no banco real

- **ID:** BUG-010
- **Data:** 2026-10-16
- **Perfil afetado:** dados reais (admin/Lucas)

## Passos para reproduzir
1. Rodar `e2e/personas` sem `PERSONAS_BASE`/`CASOS_DIR`.
2. O `_kit.js` caía nos padrões: a API de desenvolvimento e `docs/`.
3. 25 contas criadas no banco real e arquivos de resultado em `docs/` sobrescritos.

## Causa raiz
Padrões silenciosos no `_kit.js` e uma API de teste (8797) apontando para o banco real. **Em 16/10/2026 a API 8797 apontava para `avagym` (o banco real).** Além disso, a 8797 usava o mesmo `DATA_DIR` (db.json legado, vapid, mídia) da API do Lucas.

## Correção (arquivos alterados)
- `frontend/e2e/personas/_kit.js`: exige `PERSONAS_BASE` e `CASOS_DIR`; recusa as portas 4449/8787 sem `PERSONAS_ALLOW_DEV=1`.
- `app/api/db/test-db-reset.ps1` (novo): recria `avagym_test` do zero (migrations + seed + contas e2e); recusa nomes sem `_test`; para em qualquer erro.
- **Regra:** a API 8797 sobe sempre com `DB_NAME=avagym_test` e `DATA_DIR` próprio (ex.: `F:\academia\acade\data_test`), nunca no `avagym`.
- `test/qa-regressao.mjs` recusa rodar sem `DB_NAME=*_test`.
- As 25 contas **não** foram apagadas do banco real (decisão do Lucas).

## Teste de regressão adicionado
Verificado: `_kit.js` recusa sem as variáveis e contra 4449. Personas rodaram com sucesso no `avagym_test` (11/11).

## Lição / armadilha
Ferramenta de teste nunca pode ter padrão que aponte para dados reais. Banco e pasta de dados de teste próprios, com nome verificável.
