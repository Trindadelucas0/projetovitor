# BUG-018 - API do Lucas caiu ao subir com a 043: nomes de tabela já existiam desde a 001

- **ID:** BUG-018
- **Data:** 2026-10-16
- **Severidade:** ALTA (derruba a API na subida)
- **Perfil afetado:** todos (API local do Lucas fora do ar das 15:25:40 às 15:26:54, cerca de 1 min 15 s)

## Passos para reproduzir
1. Banco com a 001 (todo banco real) + 043 aplicada.
2. Subir a API com um `db.json` que tenha passkeys (`creds`).
3. Erro `coluna "extra" da relação "webauthn_credentials" não existe` em `legacy-store.js` e o processo cai.

## Causa raiz
A 043 criava `webauthn_credentials` e `push_subscriptions` com `create table if not exists`, mas a 001 já tinha tabelas com esses nomes (vazias, formato diferente, sem uso no código). O `if not exists` pulou a criação sem avisar. No avagym_test a suíte passou porque o `db.json` de teste não tinha passkeys.
O `043_down.sql` também derrubaria as tabelas da 001.

## Correção (arquivos alterados)
- Nova `app/api/db/migrations/044_ponte_legada_nomes.sql` (+ `db/down/044_down.sql`): tabelas próprias `legacy_webauthn_credentials` e `legacy_push_subscriptions`. As da 001 não são tocadas.
- `app/api/legacy-store.js`: usa os nomes novos.
- `app/api/db/down/043_down.sql`: não derruba mais as tabelas da 001; só remove os índices que a 043 criou nelas.
- Aplicado com backup antes (`backups/avagym_20261016_152625_pre-044.dump`) no avagym e no avagym_test. Na subida: 805 usuários legados, 3 passkeys, 0 push, 0 convites, 2 chaves do servidor e 3 estados importados (bate com o `db.json`); arquivos renomeados para `*.importado-*`, nada apagado.

## Teste de regressão adicionado
`v5-auditoria.mjs` (ponte legada) e a subida real conferida pelas contagens arquivo x banco.

## Lição / armadilha
Antes de `create table if not exists`, procure o nome em todas as migrations (`rg "create table <nome>" db/migrations`). Nome repetido falha calado. Para dado legado, use o prefixo `legacy_`.
