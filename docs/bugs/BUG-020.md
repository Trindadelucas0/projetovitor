# BUG-020 - Gateway de produção sem cabeçalhos de segurança (clickjacking)

- **ID:** BUG-020
- **Data:** 2026-10-16
- **Severidade:** ALTA
- **Perfil afetado:** todos (produção)

## Passos para reproduzir
1. `curl -I https://<app>/`.
2. Sem CSP/frame-ancestors, nosniff, X-Frame-Options, Referrer-Policy, Permissions-Policy (só HSTS).

## Causa raiz
O gateway Node (`/opt/avagym-runtime/gateway.mjs`) vivia fora do repo e só repassava os cabeçalhos da API em `/api`; HTML e estáticos saíam sem proteção.

## Correção (arquivos alterados)
- Novo `app/web/gateway.mjs` versionado: CSP (`frame-ancestors 'none'`, `script-src 'self' 'wasm-unsafe-eval'`), nosniff, `X-Frame-Options: DENY`, Referrer-Policy, Permissions-Policy, COOP e HSTS em toda resposta; HEAD em estáticos; `safe()` não aceita mais prefixo parecido (`dist2`).
- PM2 `avagym-web` passa a apontar para `/opt/avagym/app/web/gateway.mjs`.

## Teste de regressão adicionado
`e2e/v5-aceite-cadastro.spec.js` com `EXPECT_SEC_HEADERS=1` contra o gateway local (falha também se o console mostrar violação de CSP); specs de regressão/config/settings/auditoria rodados através do gateway.

## Lição / armadilha
Infra de produção fora do repo some do radar; tudo que serve HTML vai para o repo.
